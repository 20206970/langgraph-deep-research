# P1.3 模型路由、缓存与预算设计

## 目标

为研究图增加可配置的角色化模型路由、可追溯的 SQLite 搜索 TTL 缓存和有界的运行预算。默认行为保持兼容：所有角色回退至现有 `OPENAI_MODEL`，缓存可用但不改变来源契约，未配置 Token/金额上限时不启用相应硬限制。

## 模型路由

`src/config.py` 定义六个角色：`router`、`planner`、`summarizer`、`reporter`、`repair`、`judge`。每个角色可通过环境变量设置模型、温度和最大输出 Token；模型未设置时回退到 `OPENAI_MODEL`，连接信息继续使用现有 OpenAI 兼容配置。

`src/llm.py` 暴露 `create_llm(role="default", **overrides)`：

- `router`、`planner` 和 `repair` 使用低温度、较小输出上限；
- `summarizer` 和 `reporter` 保持较大输出上限；
- 显式 `overrides` 的优先级高于角色配置；
- 实例附带角色、模型和限额元数据，供运行记录、事件与离线评测读取。

图节点固定使用对应角色：Planner 使用 `planner`，Summarizer 使用 `summarizer`，格式修复使用 `repair`，Reporter 使用 `reporter`；会话意图分类使用 `router`。`ResearchRun.model_versions` 记录实际角色到模型的映射，`prompt_versions` 保持现有契约。

角色覆盖变量固定为 `ROUTER_MODEL`、`PLANNER_MODEL`、`SUMMARIZER_MODEL`、`REPORTER_MODEL`、`REPAIR_MODEL`、`JUDGE_MODEL`，并分别支持同前缀的 `_TEMPERATURE` 与 `_MAX_TOKENS`。未设置模型时全部回退 `OPENAI_MODEL`；默认输出上限依次为 256、1,200、4,096、4,096、1,200、1,200。价格表变量为 `MODEL_PRICING_JSON`，格式为 `{ "model-name": { "input_per_million": 0, "output_per_million": 0 } }`。

价格表通过 JSON 环境变量显式配置，键为模型名，值为每百万 input/output Token 的价格。未命中价格表时记录 `cost_status=unavailable`，绝不猜测成本。

## 搜索缓存

新增 `src/cache.py`，使用与运行记录相同 SQLite 文件中的独立 `search_cache` 表。缓存只包裹线上 `search_web` 和 `search_papers`；离线快照 fixture 不进入缓存，保证 P0.3 基线的可重复性。

缓存键为以下字段的规范 JSON 的 SHA-256：

```text
normalized_query + tool_name + provider_config_fingerprint
+ language + max_results + tool_version
```

- 查询统一去首尾空白、折叠空白并小写；
- `provider_config_fingerprint` 只使用 provider 名称、公开配置和密钥是否存在等非敏感信息，不保存密钥；
- 缓存 value 保存已归一化的来源快照、`source_id`、创建/到期时间、tool/provider 元数据；
- 命中返回原始快照，并在工具 JSON 中写入 `cache_hit=true`、`cached_at` 和 `expires_at`；缓存内容不伪装为本次实时抓取；
- TTL 到期、工具版本变更、provider 配置变化或语言变化均导致未命中；过期行在读取时删除。

缓存变量固定为 `SEARCH_CACHE_ENABLED=true`、`SEARCH_CACHE_TTL_SECONDS=86400`、`SEARCH_LANGUAGE=auto` 与 `SEARCH_TOOL_VERSION=p1.3`。

Summarizer 从本轮工具消息聚合 `cache_hit`，写入 `TaskResult.cache_hit` 和本地事件/Trace metadata。缓存故障只视为未命中，搜索流程继续执行。

## 预算

新增 JSON 可序列化的 `RunBudget` 和 `BudgetUsage`，作为 `ResearchRun` 的持久化字段，并将 schema version 升至 `2`。默认预算：

```text
max_tasks=5
max_search_attempts=3
max_format_repairs=1
max_total_tokens=null
max_estimated_cost=null
max_elapsed_seconds=300
```

对应环境变量为 `RUN_MAX_TASKS`、`RUN_MAX_SEARCH_ATTEMPTS`、`RUN_MAX_FORMAT_REPAIRS`、`RUN_MAX_TOTAL_TOKENS`、`RUN_MAX_ESTIMATED_COST` 与 `RUN_MAX_ELAPSED_SECONDS`；空值或 `0` 表示 Token/金额上限未启用。

Token 和金额上限只有显式设置后才启用；金额限额需要对应模型有价格表。预算检查点如下：

1. Planner/确认计划后：只派发前 `max_tasks` 个任务，其余任务产生 `BUDGET_EXCEEDED` 失败结果；
2. 每次搜索或格式修复前：检查总时长、累计 Token 和累计金额；超限时当前任务不再发起后续调用；
3. 每次模型响应后：提取可获得的 usage，计算已知模型成本，更新任务级 usage；
4. Reporter 前：汇总任务 usage，写入运行的 `BudgetUsage`。只要存在预算失败或已超限，报告标注范围限制，运行不能标记为伪成功。

默认保留 P0 的并行派发。并行中已启动的同级任务不可强制中断，因此全局 Token/金额/时长预算对已启动任务是协作式限制；此边界在事件、运行记录和文档中明确说明。`max_tasks`、单任务搜索次数和格式修复次数仍为严格限制。

## 评测与可观测性

离线 Runner 的 `config.json` 和每条 case-run 记录实际角色模型映射、预算配置、Token 使用、成本状态、估算成本和缓存统计。CLI 接受 `--route-label`，角色模型仍由环境变量读取；允许同一固定数据集分别写入两个不可覆盖的结果目录，再比较质量、延迟、失败率和成本。

SSE/本地事件为搜索和任务事件追加 `cache_hit`、`attempt`、`token_usage`、`estimated_cost` 和 `budget_status`，但不得包含模型原文、密钥或完整报告。LangSmith metadata 使用同一脱敏字段集。

## 错误处理

- 缓存 SQLite 不可用：记录本地诊断，退化为实时搜索；
- usage 缺失：`token_usage` 保留空值，`cost_status=unavailable`；
- 价格缺失：不计算金额，不阻止仅依赖金额的预算之外的流程；
- 预算耗尽：任务返回结构化失败，Reporter 明示未执行范围；
- 单角色模型配置无效：创建 LLM 时使用明确错误信息失败，不静默切换到未知模型。

## 验收

- 所有角色在未覆盖时回退 `OPENAI_MODEL`，覆盖时只影响目标角色；
- 相同缓存键不重复调用搜索，TTL、工具版本、provider 配置和语言变化均失效；
- 可获得/缺失 usage 与可获得/缺失价格均有测试；
- 任务数、搜索次数、格式修复、总时长和 Token/成本超限会产生显式失败，报告不伪成功；
- 固定离线数据集产物包含两套可比较的路由指纹、质量、延迟、Token 和成本字段；
- P0--P1.2 测试保持通过，不调用真实模型或外部搜索。

## 非目标

- 不实现多租户限流、分布式配额预留或正在执行请求的强制抢占；
- 不预置第三方模型价格或假设用户使用的 provider；
- 不缓存离线 fixture、完整网页正文或用户私有文档。
